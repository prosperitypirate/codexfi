# What is codexfi?

codexfi is a [Claude Code](https://code.claude.com) plugin that gives Claude **persistent, searchable memory across sessions**. Decisions, fixes, conventions, tech stack, progress, your personal preferences — everything is extracted from your sessions automatically, stored locally on your machine, and put back in front of Claude at the moment it matters.

Claude Code starts every session cold. Its built-in auto-memory keeps a short `MEMORY.md` of things Claude decides to save, and a hand-maintained Memory Bank captures the big picture — but the long tail (the exact error and its fix, the port you moved to, why you rejected library X) is gone by next week. codexfi closes that gap.

## How it works

codexfi hooks into Claude Code's lifecycle — no prompts, nothing to remember to run:

- **At session start**, Claude gets a compact `[MEMORY]` project picture: brief, architecture, tech context, progress, recent sessions, and your cross-project preferences.
- **On every prompt**, the prompt is embedded on your machine and the memories relevant to *that* prompt are injected — each memory at most once per session, never repeated.
- **After every turn**, a short-lived background worker reads the new part of the transcript and extracts typed facts (decisions, fixes, conventions, preferences, progress).
- **Mid-task**, Claude can call the `memory_search`, `memory_add`, `memory_list`, and `memory_forget` [MCP tools](/docs/api-reference/memory-tool-api).
- **Stale facts are superseded** when they change ("moved from port 8000 to 3000"), not left to contradict each other.

The `[MEMORY]` block at session start contains:

- **Project Brief** — what the project is and its goals
- **Architecture** — system design and component relationships
- **Tech Context** — stack, tools, build commands
- **Product Context** — why the project exists, problems solved
- **Progress & Status** — current state of work
- **Active Context** — what is being worked on right now
- **Recent Sessions** — summaries of the previous sessions
- **User Preferences** — cross-project personal preferences

## Zero setup

- **No API keys.** Background extraction runs through **your own Claude Code login** (`claude -p`, Haiku). Embeddings run **on your machine** (an ONNX model, downloaded once).
- **No daemon, no ports, no Docker.** Hooks return in ~0.1–0.3 s; a short-lived worker does the slow part and exits.
- **Works in the terminal and the VS Code extension.** Both use the same `~/.claude` settings, and codexfi finds the extension's bundled `claude` binary automatically.

## Quick start

In Claude Code:

```
/plugin marketplace add prosperitypirate/codexfi
/plugin install codexfi@codexfi
```

Start a new session, and Claude starts remembering. See the [Installation guide](/docs/installation) for shell install, requirements, and verification.

## Requirements

- [Claude Code](https://code.claude.com) ≥ 2.1 — terminal CLI or VS Code extension
- [Bun](https://bun.sh) or Node ≥ 22.5 on your `PATH`

That's it — no API keys.
