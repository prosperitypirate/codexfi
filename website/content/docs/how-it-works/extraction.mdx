# Extraction Pipeline

After every turn, codexfi extracts the key facts from the conversation and stores them. It all happens in a short-lived background worker, so your session never waits for it.

<DocsExtractionPipeline />

## Pipeline steps

### 1. Transcript window

The `Stop` hook only queues a job. The worker then reads the session's transcript **from the byte offset where it last stopped**, so every turn is extracted exactly once — never skipped, never repeated. User and assistant messages are formatted as plain text; codexfi's own injected `[MEMORY]` blocks are skipped, so memories are never re-extracted from themselves.

Turns longer than 12,000 characters are split into windows on message boundaries rather than truncated.

### 2. LLM extraction

Each window is sent to the LLM with a system prompt instructing it to identify durable facts. By default this is **your own Claude Code**:

```bash
claude -p --safe-mode --model haiku --output-format json --tools "" …
```

`--safe-mode` keeps your normal login while skipping plugins, hooks, `CLAUDE.md`, MCP servers, and auto-memory, and the call runs in a neutral temp directory — roughly 600 tokens of overhead per call. You can switch to the Anthropic API with an API key instead; see [Configuration](/docs/configuration#llm-backend).

The LLM returns a JSON array of typed facts:

```json
[
  {
    "memory": "Auth uses JWT stored in httpOnly cookies, not localStorage",
    "type": "architecture"
  },
  {
    "memory": "User prefers bun over npm for all installs",
    "type": "preference"
  }
]
```

Each fact is an atomic, self-contained piece of knowledge with an assigned [memory type](/docs/how-it-works/memory-types).

### 3. Embedding

Each fact is embedded **on your machine** with an ONNX model (default `jina-embeddings-v2-base-code`, 768 dimensions), loaded through transformers.js. The weights are downloaded once into `~/.codexfi/models`; after that, embedding needs no network. Voyage AI `voyage-code-3` is available as an option if you prefer it and have a key.

Every memory records which model produced its vector, and only vectors from the same model are ever compared.

### 4. Deduplication

<DocsDedupCosine />

Before storing, each fact is compared with existing memories. Thresholds are tuned per embedding model; with the default local model:

| Memory category | Dedup distance | Meaning |
|----------------|-----------------|---------|
| General types | 0.16 | Very close matches are considered duplicates |
| Structural types | 0.34 | Wider threshold — structural knowledge evolves |

If a duplicate is found, the existing memory is **updated** in place — text, vector, and type are refreshed — instead of adding a copy.

### 5. Storage

New memories are inserted into the local SQLite store with:

- A UUID identifier
- The memory text
- The embedding vector and the model that produced it
- Metadata (type, scope, date)
- Source chunk (the conversation excerpt that produced this fact)
- Timestamps (created_at, updated_at)

### 6. Aging rules

After insertion, type-specific aging rules run:

- **`progress`** and **`active-context`**: only the latest survives
- **`session-summary`**: the newest 3 are kept; older ones are condensed into a `learned-pattern`

### 7. Contradiction detection

The worker finds semantically nearby memories and asks the LLM: "Does this new fact supersede any of these?" Superseded memories are marked `superseded_by` the new one — they stay in the database but are excluded from search and from the `[MEMORY]` block.

## Extraction modes

### Turn mode

Queued by the `Stop` hook after every turn. Extracts atomic facts from the new part of the transcript.

### Summary mode

Queued by `PreCompact` and `SessionEnd`. The worker first extracts any turns not yet processed, then writes a `session-summary` covering what was worked on, decisions made, and progress.

### Init mode

Queued on a project's first session, when it has no memories yet. Reads 28 common project files (README, package.json, Dockerfile, tsconfig, monorepo configs, agent instructions like `CLAUDE.md` and `AGENTS.md`, and more) plus the last 20 git commits, and extracts foundational facts with a dedicated init prompt. Disable with `"autoInit": false`.

## The background worker

- **One worker per machine.** An exclusive lock file ensures a single worker, with takeover if a previous one died. Several concurrent Claude Code sessions share one queue.
- **Exits when idle.** There is no daemon: the worker starts when a job is queued and exits when the queue is empty.
- **No recursion.** codexfi's own `claude -p` calls run with `--safe-mode` and `CODEXFI_DISABLE=1`, so they can never trigger codexfi hooks.
- **Failures never reach your session.** Failed LLM calls are retried with exponential backoff and jitter; if extraction still fails, that turn is skipped and logged to `~/.codexfi/logs/worker.log`.

## JSON parsing

LLM responses are parsed with tolerance for common quirks:

- Markdown code fences (` ```json ... ``` `) are stripped
- Plain string arrays are accepted (items default to `learned-pattern` type)
- Wrapped objects (`{"memories": [...]}`) are unwrapped
- Parse failures return an empty array — zero memories for this turn, no error

## Privacy

Before extraction, content wrapped in `<private>...</private>` tags is stripped. Nothing inside private tags is sent to the LLM or stored in the database. Directories listed in [`excludePaths`](/docs/configuration#excludepaths) are never read at all.
