# Configuration

codexfi needs **no configuration**. Out of the box, background extraction runs through your Claude Code login and embeddings run on your machine. Everything below is optional.

## Config file

Settings live in `~/.codexfi/codexfi.jsonc`. The file doesn't exist until you create it, and every field is optional:

```jsonc
// ~/.codexfi/codexfi.jsonc
{
  "llmBackend": "auto",              // "auto" | "claude-cli" | "anthropic-api"
  "llmModel": "haiku",               // any Claude Code model alias or id
  "localModel": "jina-v2-base-code", // or "all-MiniLM-L6-v2" (lighter, faster)
  "memoryBank": "auto",              // "auto" | "off"
  "autoInit": true,                  // seed a new project from README/manifests/git log
  "excludePaths": ["/Users/me/clients/secret-co"],  // codexfi stays silent here
  "anthropicApiKey": ""              // only for llmBackend "anthropic-api"
}
```

`codexfi status` reports whether the file was found and which backends are active.

## LLM backend

Background work — extraction, session summaries, contradiction checks — needs an LLM. By default that's **your own Claude Code**.

### `llmBackend`

- **Default:** `"auto"`

| Value | Behavior |
|-------|----------|
| `auto` (default) | Use the `claude` CLI if one is found; otherwise use the Anthropic API if `anthropicApiKey` is set |
| `claude-cli` | Always call `claude -p` — your Claude Code login (subscription or whatever Claude Code is set up with) |
| `anthropic-api` | Always call the Anthropic Messages API with `anthropicApiKey` |

The CLI call runs `claude -p --safe-mode` in a neutral temp directory with no tools, no plugins, no hooks, no `CLAUDE.md`, and no session persistence — about 600 tokens of overhead per call. codexfi never handles your credentials; it invokes your own, unmodified Claude Code binary. The `claude` binary is located via `CODEXFI_CLAUDE_BIN`, the binary Claude Code reports to hooks (this is how the VS Code extension's bundled binary is found), your `PATH`, then known install directories.

### `llmModel`

- **Default:** `"haiku"`

The model for background work. CLI aliases such as `"haiku"` or `"sonnet"` resolve to the newest model of that tier your Claude Code offers; full model ids work too.

### `anthropicApiKey`

Only used when `llmBackend` is `"anthropic-api"` (or `"auto"` without Claude Code on the machine). Falls back to the `ANTHROPIC_API_KEY` environment variable.

## Embeddings

Embeddings are **local-only**: an on-device ONNX model via transformers.js. No key, and no network after the one-time model download (weights are cached in `~/.codexfi/models`). Memory text is never sent to a third-party embedding API. (Remote embedding providers were removed in 1.0; legacy `embeddingProvider` / `voyageApiKey` entries in an old config file are ignored.)

### `localModel`

- **Default:** `"jina-v2-base-code"`

| Model | Dimensions | Size | Notes |
|-------|-----------|------|-------|
| `jina-v2-base-code` (default) | 768 | ~160 MB | Best local model for code-assistant memories |
| `all-MiniLM-L6-v2` | 384 | ~23 MB | Lightweight option for slower machines |

Every memory records which embedding model produced its vector, and only vectors from the current model are ever compared. If you switch models (or upgrade from 0.7.x), the background worker re-embeds older rows in batches; structured memories stay usable in the meantime.

## Behavior

### `memoryBank`

- **Default:** `"auto"`

When a `memory-bank/` directory is found in the project (or up to four parent directories), codexfi stops duplicating it: at session start it injects only session summaries newer than your last bank save plus your cross-project preferences. Per-prompt retrieval is unchanged. Set `"off"` to always inject the full project picture. See [Memory Bank](/docs/guides/claude-code-setup#memory-bank).

### `autoInit`

- **Default:** `true`

On a project's first session (no memories yet), seed memory in the background from the project's own files and recent git log.

### `excludePaths`

- **Default:** `[]`

Absolute directory prefixes where codexfi stays **completely silent** — no injection, no extraction, and the MCP tools refuse to read or write. Use it for client work or anything you don't want remembered.

```jsonc
{
  "excludePaths": ["/Users/me/clients", "/Users/me/scratch/secret"]
}
```

### `keywordPatterns`

- **Default:** built-in patterns

When a prompt matches one of these patterns, codexfi adds a short note pointing Claude at the `memory_add` tool. Built-in patterns include: `remember`, `memorize`, `save this`, `note this`, `keep in mind`, `don't forget`, `learn this`, `store this`, `record this`, `make a note`, `take note`, `jot down`, `commit to memory`, `never forget`, `always remember`.

Custom patterns (regular expressions) are appended to the built-in list:

```jsonc
{
  "keywordPatterns": ["bookmark this", "save for later"]
}
```

## Retrieval and rendering

### `similarityThreshold`

- **Default:** model-specific (`0.38` for `jina-v2-base-code`)

Minimum similarity for a memory to be retrieved. Lower values return more results; higher values are stricter.

### `displaySimilarityThreshold`

- **Default:** model-specific (`0.50` for `jina-v2-base-code`)

Minimum similarity for a memory to be *shown* in the **Relevant to Current Task** block. Retrieval still runs at `similarityThreshold`; this is a display filter on top.

### `maxMemories`

- **Default:** `20`

Maximum user-scoped memories retrieved per prompt.

### `maxProjectMemories`

- **Default:** `20`

Maximum project-scoped memories retrieved per prompt.

### `maxStructuredMemories`

- **Default:** `100`

Maximum memories fetched for the structured session-start sections (Project Brief, Architecture, Tech Context, and so on). Per-section caps apply on top.

### `maxProfileItems`

- **Default:** `8`

Maximum items in the **User Preferences** section.

### `injectProfile`

- **Default:** `true`

Set to `false` to leave user preferences out of the session-start block.

### `userContainerTag` / `projectContainerTag`

- **Default:** auto-generated (user: from your git email; project: from the directory path)

Override the user or project scope. Useful to link several directories to the same project memory.

## Environment variables

These override the config file — mostly for development and CI:

| Variable | Overrides |
|----------|-----------|
| `CODEXFI_DATA_DIR` | Data directory (default `~/.codexfi`) |
| `CODEXFI_LLM_BACKEND` | `llmBackend` |
| `CODEXFI_LLM_MODEL` | `llmModel` |
| `CODEXFI_LOCAL_MODEL` | `localModel` |
| `CODEXFI_MODEL_DIR` | Where local model weights are cached |
| `CODEXFI_CLAUDE_BIN` | Path to the `claude` binary |
| `CODEXFI_DISABLE=1` | Turns every codexfi entrypoint into a no-op |

## Data storage

Everything is local, under `~/.codexfi/`:

| Path | Contents |
|------|----------|
| `~/.codexfi/codexfi.jsonc` | Configuration (optional) |
| `~/.codexfi/store/store.db` | SQLite database (WAL mode) — all memories with their vectors |
| `~/.codexfi/models/` | On-device embedding model weights |
| `~/.codexfi/queue/` | Background job queue |
| `~/.codexfi/sessions/` | Per-session state (transcript cursor, memories already shown) |
| `~/.codexfi/logs/` | `hook.log` and `worker.log` |

SQLite's WAL mode lets several Claude Code sessions read the store at once while a single background worker writes.
