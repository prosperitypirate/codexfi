# Memory Tools (MCP)

Hooks cover the automatic path — inject at session start and per prompt, extract after every turn. For deliberate, agent-initiated memory work, the codexfi plugin also ships a stdio **MCP server** named `codexfi` with four tools. Claude Code starts it automatically when the plugin is enabled; there is nothing to configure.

| Tool | Purpose |
|------|---------|
| [`memory_search`](#memory_search) | Semantic search over memories from past sessions |
| [`memory_add`](#memory_add) | Store a fact verbatim |
| [`memory_list`](#memory_list) | List the most recently updated memories |
| [`memory_forget`](#memory_forget) | Delete a memory by id |

The server tells Claude when to reach for these: search when it needs history that isn't already in context (past decisions, earlier fixes, conventions, previous sessions), and add when you ask it to remember something or a durable fact is settled. Memories are notes from past sessions — Claude is told to verify against the code before relying on them for anything risky.

## `memory_search`

Semantic search over memories (decisions, fixes, conventions, preferences).

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `query` | Yes | — | What to look for, in natural language |
| `scope` | No | `"all"` | `"project"`, `"user"`, or `"all"` |
| `limit` | No | `10` | Maximum results (up to 50) |

```json
{ "query": "how is authentication handled", "scope": "project", "limit": 5 }
```

**Returns** one line per match, sorted by score:

```
- [a3f82b10 · project · architecture · 87% · 2026-02-20] Auth uses JWT stored in httpOnly cookies, refresh token rotation every 7 days.
```

List-style queries ("every preference", "all the bugs we fixed") also match by memory type, so enumeration isn't limited to the closest semantic hits.

## `memory_add`

Store a durable fact verbatim — no extraction call. Write it as a self-contained statement, including the *why*.

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `content` | Yes | — | The fact to remember |
| `type` | No | `"learned-pattern"` | One of the [memory types](/docs/how-it-works/memory-types); `preference` for user habits |
| `scope` | No | `"project"` | `"project"` (this repo) or `"user"` (cross-project) |

```json
{
  "content": "Project uses PostgreSQL 16 with the pgvector extension for vector storage",
  "type": "tech-context",
  "scope": "project"
}
```

The fact is embedded and deduplicated like any other memory — a near-duplicate updates the existing entry instead of adding a copy. `<private>…</private>` content is stripped first, and content that is entirely private is refused.

**Returns**: `Stored project memory 7cd91e44 (tech-context).` — or `Updated existing …` when it matched an existing memory.

## `memory_list`

List the most recently updated memories, optionally filtered by type. No semantic matching.

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `scope` | No | `"project"` | `"project"` or `"user"` |
| `type` | No | — | Only memories of this type |
| `limit` | No | `20` | Maximum results (up to 100) |

```json
{ "type": "session-summary", "limit": 10 }
```

**Returns** one line per memory: `- [id · type · updated] memory`.

## `memory_forget`

Delete a memory permanently.

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `id` | Yes | — | Full id, or a unique prefix of at least 8 characters |

Only memories in the current project or your user scope can be deleted. An ambiguous prefix is rejected with the number of matches.

```json
{ "id": "a3f82b10" }
```

## Scopes

### `project`

Project-scoped memories are tied to the project directory. The project tag is a deterministic hash of the path, so the same directory always maps to the same memory namespace.

Use project scope for: architecture decisions, tech stack, error solutions, progress, project-specific configuration.

### `user`

User-scoped memories are tied to your identity (derived from your git email) and follow you across all projects.

Use user scope for: coding preferences, communication style, tool preferences, workflow patterns.

## Memory types for `memory_add`

| Type | When to use |
|------|------------|
| `project-brief` | What the project is, its purpose |
| `architecture` | System design, component relationships |
| `architecture-pattern` | Repeatable workflows, recipes, procedural conventions (e.g. PR workflow, migration patterns) |
| `tech-context` | Stack, languages, frameworks, key dependencies — not specific commands or tool paths (use `project-config`) |
| `product-context` | Features, goals, product decisions |
| `progress` | Current state, what's done, what's blocked |
| `active-context` | What is being worked on right now (singleton — only latest survives) |
| `project-config` | Config preferences, run commands, env setup |
| `error-solution` | Bug fixes, workarounds discovered |
| `preference` | User coding preferences (typically user-scoped) |
| `learned-pattern` | Patterns observed across sessions |

If no type is given, it defaults to `learned-pattern`.

## Triggering explicit saves

Just ask in natural language:

- "Remember that we use JWT in httpOnly cookies"
- "Save this: the API rate limit is 100 req/min"
- "Don't forget that tests must pass before merging"
- "Note this for future sessions"

When a prompt matches one of these patterns, codexfi adds a short note pointing Claude at `memory_add`. The patterns are configurable via [keywordPatterns](/docs/configuration#keywordpatterns). Every turn is also extracted automatically in the background, so nothing depends on the tool being called.

## `excludePaths`

In a directory covered by [`excludePaths`](/docs/configuration#excludepaths), every tool refuses with `codexfi is disabled for this directory (excludePaths).` — the privacy switch applies to explicit tool calls too.

## Example session

```
You: Remember that this project uses PostgreSQL 16 with pgvector.

Claude calls memory_add:
  { "content": "Project uses PostgreSQL 16 with the pgvector extension for vector storage",
    "type": "tech-context" }
  → Stored project memory 7cd91e44 (tech-context).

— next week, new session —

You: Which database are we on, and why did we pick it?

[MEMORY] block (injected for this prompt):
  ## Relevant to Current Task
  - [87%] Project uses PostgreSQL 16 with the pgvector extension for vector storage

Claude: You're on PostgreSQL 16 with the pgvector extension …
```
