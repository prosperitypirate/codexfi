# Test Suite

codexfi ships with a three-tier test suite that verifies the memory system from vector math and storage through to the Claude Code hooks, the background worker, and the MCP tools.

<DocsTestTiers />

## What is verified

| Area | What it guarantees for you |
|---|---|
| Vector store | Memories are stored, filtered, and searched correctly; cosine math and serialisation are exact |
| Deduplication & supersede | Near-duplicates update in place; changed facts replace stale ones instead of contradicting them |
| Aging | Only the latest `progress` / `active-context` survives; old session summaries condense into lasting patterns |
| Transcript reading | Each turn is extracted exactly once; long turns are windowed, not truncated; codexfi's own `[MEMORY]` blocks are never re-extracted |
| Context building | The `[MEMORY]` block renders every section in order, applies per-type caps and display thresholds, and doesn't repeat a fact across sections |
| Hooks & MCP tools | Hook handlers inject and enqueue correctly; the MCP tools search, add, list, and forget memories |
| Auto-init | A new project is seeded from its own files and git log |
| LLM backend | The `claude -p --safe-mode` call is built correctly and parsed robustly; the Anthropic API backend works as a fallback |
| Configuration | Every setting in `codexfi.jsonc` is read, validated, and defaulted correctly |
| Multi-session safety | Many processes reading and writing the same SQLite store concurrently lose no data |

## Fully offline

The suite needs **no API keys and no network**. A test preload isolates every run from your machine before any plugin code loads:

- a temporary `HOME` and `CODEXFI_DATA_DIR`, so your real `~/.codexfi` is never touched
- a fake `claude` binary, so no test can reach your Claude Code login
- a deterministic stand-in for the on-device embedding model (no weight download)
- a mocked LLM for extraction, summaries, and contradiction checks
- API keys and Claude Code environment variables removed

## For contributors

### Test tiers

| Tier | What runs |
|---|---|
| **Unit** | Cosine math, CRUD, filters, serialisation, config, prompts, transcript reader, context builder, LLM backend, auto-init, telemetry |
| **Integration** | Real SQLite store (under both `bun:sqlite` and `node:sqlite`), store pipeline, embeddings, hooks, MCP server, plugin loading, aging |
| **Stress** | 20 real OS processes hitting the same SQLite file — concurrent writes, reads, and mixed |

The stress tests validate the scenario where several Claude Code sessions and the background worker use the same `store.db` at once. Each test spawns real child processes (not async work within one process) to match how codexfi actually runs.

### Running the tests

```bash
cd testing
bun install                 # first time only
bun run test                # unit + integration
bun test src/unit/          # unit only
bun test src/integration/   # integration only
bun test src/stress/        # concurrent stress tests
```

### Trying the plugin end to end

To try a working-tree build in a real Claude Code session without installing it:

```bash
(cd plugin && npm install && npm run build)   # or: bun install && bun run build
claude --plugin-dir ./plugin                  # loads the working tree for one session
```

Point `CODEXFI_DATA_DIR` at a scratch directory first to keep your real memories out of it. Logs are written to `$CODEXFI_DATA_DIR/logs/{hook,worker}.log`.
